# Codex 额度窗口自适应显示任务书

## 1. 文档信息

- 状态：待实施
- 编写日期：2026-07-15
- 目标分支：`codex/quota-window-adaptive-display`
- 基线分支：`master`
- 实施原则：依据运行时返回的窗口时长显示额度，不根据尚未明确的官方政策硬编码界面

## 2. 背景

Codex App 当前只显示周额度。本机对当前 Pro 账号执行实时查询后，服务端返回的主额度结构为：

```text
primary.windowDurationMins = 10080
primary.usedPercent = 3
secondary = null
```

`10080` 分钟等于 7 天，因此当前返回的是周额度，不是 5 小时额度。

现有小组件虽然已经把 `window_minutes` 保存到 `QuotaWindow`，但后续展示仍把 `primary` 固定解释为“5小时”、把 `secondary` 固定解释为“周额度”。当服务端只在 `primary` 中返回周额度时，小组件会把真实的周额度错误显示成 5 小时额度。

OpenAI 当前公开说明与账号实际返回结构尚未完全一致。本任务不判断 5 小时额度是否会永久取消，而是消除小组件对 `primary`、`secondary` 固定含义的依赖。

## 3. 目标

1. 根据 `window_minutes` 识别并显示额度窗口名称。
2. 同时兼容旧的“5 小时 + 周额度”结构和当前的“仅周额度”结构。
3. 服务端以后恢复 5 小时窗口时，小组件无需再次修改即可自动显示。
4. 服务端返回未知窗口时，不猜测其政策含义，使用中性名称。
5. CLI 单次输出、桌面小组件、托盘提示使用同一套窗口解释结果。
6. 保持现有额度来源选择、缓存、状态灯和 Hook 状态逻辑不变。

## 4. 非目标

- 不删除 5 小时额度支持。
- 不新增“是否启用 5 小时额度”的配置项或功能开关。
- 不根据账号套餐名称推断窗口类型。
- 不把诊断时使用的 app-server 直接查询加入正式运行流程。
- 不修改额度事件的新旧来源选择、时间排序和同账号缓存策略。
- 不调整无额度、待确认、工作中、闲置中等状态优先级。
- 不进行与额度窗口显示无关的重构或 UI 美化。
- 本任务不包含打包、发布、推送或创建 GitHub Release。

## 5. 输入与显示契约

### 5.1 窗口识别规则

| `window_minutes` | 显示名称 | 重置时间格式 |
|---:|---|---|
| `300` | `5小时` | 当天仅显示时分；跨天显示月、日和时分 |
| `10080` | `周额度` | 始终显示月、日和时分 |
| 其他有效值 | `额度`；第二个未知窗口使用 `额外额度` | 显示月、日和时分 |
| `None` | 不根据 `primary` 或 `secondary` 猜测窗口类型 | 有真实额度数据时使用中性名称 |

只允许使用窗口时长判断“5小时”或“周额度”。`primary`、`secondary` 仅表示服务端返回位置，不再表示业务含义。

### 5.2 窗口有效性

满足以下任一条件时，窗口视为有数据：

- `window_minutes` 不为 `None`；
- `used_percent` 不为 `None`；
- `resets_at` 不为 `None`。

完全空的窗口不占用 UI 行，也不在 `--once` 输出中生成空行。

如果两个窗口都完全为空，保留一行中性占位信息：

```text
额度：未读取 未知
```

### 5.3 排序规则

已识别窗口按以下顺序显示：

1. `5小时`
2. `周额度`
3. 其他未知窗口，保持原始返回顺序

当前结构只有周额度时，周额度占第一行，第二行隐藏。

### 5.4 兼容矩阵

| 场景 | 原始窗口 | 预期显示 |
|---|---|---|
| 旧结构 | `primary=300`，`secondary=10080` | 两行：`5小时`、`周额度` |
| 当前结构 | `primary=10080`，`secondary=null` | 一行：`周额度` |
| 仅 5 小时 | `primary=300`，`secondary=null` | 一行：`5小时` |
| 返回顺序变化 | `primary=10080`，`secondary=300` | 两行：`5小时`、`周额度` |
| 单个未知窗口 | 一个有效窗口，时长不是 `300/10080` | 一行：`额度` |
| 两个未知窗口 | 两个有效未知窗口 | 两行：`额度`、`额外额度` |
| 完全未读取 | 两个窗口均为空 | 一行：`额度：未读取 未知` |

## 6. 设计约束

### 6.1 数据层

`QuotaWindow.window_minutes` 已存在，继续作为窗口识别依据，不新增政策状态字段。

`QuotaSnapshot.primary` 和 `QuotaSnapshot.secondary` 继续保留原始数据含义，避免影响额度来源读取、缓存和无额度判断。

### 6.2 快照层

在快照构建阶段增加一个窄范围的窗口规范化函数：

```text
原始 primary/secondary
        ↓
过滤完全空窗口
        ↓
根据 window_minutes 命名
        ↓
按 5小时、周额度、未知窗口排序
        ↓
生成最多两条显示记录
```

不建立通用额度注册表，不增加套餐策略类，不把一次显示修复扩展为配置系统。

`CodexSnapshot` 应为两个现有显示槽提供以下信息：

- 动态标题；
- 对应的 `QuotaWindow`；
- 完整文本；
- 是否可见。

现有 `primary_text`、`secondary_text` 可以保留，但其前缀必须来自动态标题，不能继续硬编码。

### 6.3 UI 层

UI 刷新时必须先更新动态标题和行可见性，再填充百分比与重置时间。

隐藏第二行时：

- 标题、重置时间、百分比三个控件同时隐藏；
- 不留下空白额度行；
- 高度计算只统计可见额度行；
- 托盘提示不包含隐藏行或空行。

服务端以后恢复两个窗口时，隐藏行必须能够在下一次刷新时重新显示。

### 6.4 CLI 输出

`python main.py --once` 只打印可见额度行。

当前账号的预期结构类似：

```text
状态：工作中
周额度：97% 7-21 20:22
```

不得继续输出被误标的 `5小时：97%`，也不得输出空的第二行。

### 6.5 状态逻辑

状态灯仍应检查所有真实额度窗口是否耗尽。窗口显示顺序、标题变化或 UI 行隐藏不得改变以下行为：

- 任一有效额度达到 100%，且重置时间仍在未来，可以进入“无额度”；
- 明确的 cooldown、usage limit、rate limit 错误仍可以触发“无额度”；
- 普通文本中出现 `quota` 不触发“无额度”。

## 7. 预计修改范围

| 文件 | 任务 |
|---|---|
| `codex_widget/models.py` | 为现有两个显示槽补充动态标题和可见性数据 |
| `codex_widget/snapshot.py` | 规范化窗口、动态命名、排序并生成显示文本 |
| `codex_widget/ui.py` | 应用动态标题、控制整行显隐并修正高度计算 |
| `main.py` | `--once` 只打印可见额度行 |
| `tests/test_snapshot.py` | 覆盖新旧额度结构、未知窗口和无额度状态 |
| `tests/test_ui_note.py` | 覆盖动态标题、单行/双行切换和隐藏行恢复 |

除非实现过程中发现直接依赖，否则不修改其他文件。

任务：

## 9. 分支与合并策略

本任务的合并条件是“兼容所有已知额度结构”，不是“OpenAI 正式宣布取消 5 小时额度”。

- 如果后续继续只有周额度：分支直接适用。
- 如果后续恢复 5 小时额度：同一实现应自动重新显示 5 小时行，分支仍然适用。
- 如果后续同时返回 5 小时和周额度：显示两行，分支仍然适用。
- 如果后续返回未知时长：使用中性名称，不阻塞小组件运行。
- 只有服务端彻底移除窗口时长，或返回结构发生本任务无法兼容的重大变化时，才重新评估分支，而不是因为 5 小时额度恢复就放弃分支。

合并前必须完成阶段 A 至 E，并基于本任务书进行一次独立审查。未完成审查前不合并到 `master`。
