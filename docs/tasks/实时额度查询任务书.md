# Codex 实时额度查询任务书

## 1. 文档信息

- 状态：待实施
- 编写日期：2026-08-07
- 目标分支：`codex/realtime-quota-query`
- 基线分支：`master`
- 实施原则：实时查询优先，本地日志和缓存兜底；任务开始后原则上不修改本任务书，实施过程中的新发现写入验证报告或审查报告。

## 2. 背景简述

当前小组件主要从本地 `codex.rate_limits`、session `token_count` 和 `quota_cache.json` 读取额度。该方案在冷启动、当天未使用 Codex、或日志尚未刷新时可能只能显示旧缓存，不能主动确认实时额度。

前期只读探索已验证可通过独立 Codex app-server 查询实时额度：

```text
%USERPROFILE%\.codex\plugins\.plugin-appserver\codex.exe app-server --stdio
```

协议顺序为 `initialize`、`initialized`、`account/read`、`account/rateLimits/read`。实测返回中存在多个额度池，应优先选择 `limitId == "codex"`，避免误用 `codex_bengalfox` 等模型专属池。

## 3. 总目标

1. 小组件优先通过独立 app-server 实时查询 Codex 主额度。
2. 实时查询不依赖正在运行的 ChatGPT App 窗口或其内部 app-server 进程。
3. 查询成功后复用现有 `QuotaWindow`、`QuotaSnapshot`、窗口命名和状态灯逻辑。
4. 查询失败时自动回退到现有本地日志/session/cache 读取。
5. 全流程不输出、不记录、不缓存 token、完整账号 ID、邮箱或原始认证头。

## 4. 范围边界

### 4.1 必须做

- 新增 app-server 实时额度读取器。
- 在现有额度读取流程前接入实时读取。
- 实现 `codex` 主额度池选择。
- 实现 app-server 启动失败、超时、认证失败、协议错误和结构变化时的安全回退。
- 补充目标测试和 README 说明。

### 4.2 不做

- 不直接依赖未公开验证的 ChatGPT 私有 rate limit HTTP URL。
- 不移除现有本地日志、session 和同账号缓存读取逻辑。
- 不改变 Hook 工作/闲置/等待状态机。
- 不改变额度窗口显示规则和 UI 视觉样式。
- 不新增账号登录流程。
- 不把 app-server 原始响应全量写入持久缓存。
- 不打包、不发布、不推送、不创建 GitHub Release。

## 5. 实施阶段

### 阶段 A：建立分支与基线检查

任务：

1. 确认 `master` 工作区干净。
2. 从 `master` 创建 `codex/realtime-quota-query`。
3. 运行现有完整测试，确认实现前基线状态。
4. 运行一次脱敏 app-server 探针，确认当前机器仍可实时查询。

验证：

```powershell
git status --short
git branch --show-current
uv run pytest
```

验收标准：

- 当前分支为 `codex/realtime-quota-query`。
- 开发前没有无关 dirty 文件。
- 完整测试结果明确。
- 探针输出只包含字段结构和脱敏额度信息，不包含 token、邮箱或完整账号 ID。

### 阶段 B：实现 app-server 实时读取器

任务：

1. 新增 app-server 可执行文件发现逻辑。
2. 按顺序查找：
   - `%USERPROFILE%\.codex\plugins\.plugin-appserver\codex.exe`
   - `%USERPROFILE%\.codex\.sandbox-bin\codex.exe`
   - `PATH` 中的 `codex`
3. 新增 stdio JSON-RPC 客户端，负责启动进程、发送请求、读取响应、处理 stderr、超时和清理进程。
4. 实现 `initialize`、`initialized`、`account/read`、`account/rateLimits/read`。
5. 将 app-server 响应解析成现有 `QuotaSnapshot`。
6. 所有异常使用脱敏错误，不暴露认证信息。

验证：

```powershell
uv run pytest tests/test_app_server_quota_reader.py
```

验收标准：

- mock 正常响应可生成有效 `QuotaSnapshot`。
- 未初始化、JSON-RPC error、无效 JSON、stderr 噪声、超时和进程启动失败都能安全失败。
- 子进程在成功、失败和超时后都被清理。
- 错误消息不包含 token、完整账号 ID、邮箱或 bearer header。

### 阶段 C：实现额度池选择与字段映射

任务：

1. 优先选择 `result.rateLimitsByLimitId["codex"]`。
2. 无该字段时，使用 `result.rateLimits` 且 `limitId == "codex"`。
3. 仍无明确 `codex` 池时，才允许使用顶层 `result.rateLimits` 作为回退。
4. 映射字段：
   - `usedPercent` -> `used_percent`
   - `windowDurationMins` -> `window_minutes`
   - `resetsAt` -> `resets_at`
   - `rateLimitReachedType` -> 限额信号输入
5. 支持 `resetsAt` 为 Unix 秒时间戳；保留现有 ISO 时间解析能力。

验证：

```powershell
uv run pytest tests/test_app_server_quota_reader.py tests/test_snapshot.py
```

验收标准：

- `codex` 池优先级高于 `codex_bengalfox`。
- 顶层 `rateLimits` 可作为兼容回退。
- `primary` 和 `secondary` 都能正确映射。
- `windowDurationMins = 10080` 后续仍显示为“周额度”。
- `rateLimitReachedType` 不丢失，额度耗尽判断无回归。

### 阶段 D：接入现有读取流程

任务：

1. 在 `CodexQuotaReader.read_quota()` 中优先尝试实时读取。
2. 实时读取成功时返回实时结果。
3. 实时读取失败时执行现有本地日志/session/cache 读取。
4. 保留同账号缓存机制；如缓存实时结果，只缓存现有精简 `rate_limits` 数据。
5. 保持现有状态灯、Hook 状态和 note 展示规则不变。

验证：

```powershell
uv run pytest tests/test_quota_reader.py tests/test_snapshot.py tests/test_ui_note.py
```

验收标准：

- 实时读取成功时优先使用实时额度。
- app-server 不存在、启动失败、认证失败、网络失败、协议错误、超时或结构不可识别时，自动回退本地读取。
- 回退路径保持现有行为，旧测试不需要降低断言。
- 普通实时查询失败不触发“无额度”。
- 用户可见 note 不显示内部额度池名或调试来源，除非需要给出可操作错误。

### 阶段 E：实机验证
